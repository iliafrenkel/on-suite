# AI access P3 — ON Notes tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A connected assistant can search the user's ON Notes outline, read a part of it, list what's due, and (with `notes:write`) add a bullet and tick one done.

**Architecture:** ON Notes implements `app.ToolProvider` in a new `internal/apps/notes/tools.go`. There are five tools, each a thin wrapper over an existing `Store` method (`Search`, `ByID`, `Outline`, `AncestorsMany`, `Due`, `Create`, `SetDone`). The JSON argument and result helpers that Books keeps privately move to `internal/platform/app`, so both apps (and P4) share one copy. No migrations, routes or dependencies.

**Tech Stack:** Go 1.27, existing SQLite store, `modelcontextprotocol/go-sdk` through the platform only.

**Spec:** `docs/superpowers/specs/2026-11-24-ai-access-mcp-design.md` ("Tool rules", "Tool list" → Notes, "Phases" → P3). P2 plan for the pattern: `docs/superpowers/plans/2026-11-25-ai-access-p2.md`.

## Global Constraints

- The tool set is exactly the spec's five. The same "spec only" rule Ilia set for P2 applies: no due-date, move, delete or edit tools.
  - `notes_search` (read)
  - `notes_get` (read)
  - `notes_due` (read)
  - `notes_add` (write)
  - `notes_set_done` (write)
- Scopes are `notes:read` and `notes:write`. Reads have `ReadOnly: true`. Writes have `ReadOnly: false`. `Idempotent` is true for `notes_set_done` and false for `notes_add`.
- `Call` uses only the `userID` it is given. Every store method used already scopes to that user.
- A missing note, another user's note and an archived note all give the same message, verbatim: `No note with that ID in your outline`.
- `ErrTooDeep` is shown as `That would nest the outline too deeply.`
- `ErrInvalid` is shown as the store's own detail, made into a sentence. For example `notes: invalid note: the title is longer than 2000 characters` becomes `The title is longer than 2000 characters.`
- Any other error stays a plain error, so the model sees "Something went wrong."
- Malformed arguments give `The arguments are not valid.` (shared helper, see Task 1).
- Long text is capped at 200,000 characters, with a note when cut (spec, "Tool rules"). `notes_get` is capped; `notes_search` (at most 50 results) and `notes_due` are not, which is fine at household scale.
- Archived bullets, and everything under them, never appear in any result (spec §13 of the Notes design; `Search`, `Due` and `Outline` already exclude them).
- No deletes.

## Review Focus

1. **A huge outline.** `notes_get` with no id on a big outline must stop at 200,000 characters with the truncation note, not send megabytes.
2. **Depth limit hides children.** A bullet at the depth limit that has children must say so (`(+N more)`). Otherwise the model will think it has none and won't ask for more.
3. **Archived ids.** An archived bullet's id (left in the model's context from an earlier call) must get the not-found message from `notes_get`, `notes_add` (as parent) and `notes_set_done`. It must not reveal the archived bullet's text.
4. **Multi-line text in `notes_add`.** "Shopping list: milk, bread" on one line, or text with line breaks. The first line becomes the title and the rest becomes the bullet's note. Nothing is lost.
5. **Empty text.** `notes_add` with blank text must refuse. The store allows empty titles for the UI's Enter key, but an assistant adding an empty bullet is always a mistake.

## Task 2: Notes read tools — search, get, due

**Files:**
- Create: `internal/apps/notes/tools.go`
- Test: `internal/apps/notes/tools_test.go`

**Interfaces:**
- Consumes: `app.ParseToolArgs`, `app.MarshalTool`, `app.CapToolText`, `app.ToolError` (Task 1). Also these store methods:
  - `Store.Search(ctx, userID, query, showCompleted)`
  - `Store.ByID`
  - `Store.Outline(ctx, userID, rootID, showCompleted, ignoreCollapsed)`
  - `Store.AncestorsMany(ctx, userID, ids)`
  - `Store.Due(ctx, userID, "")`
  - `GroupByDue(rows, today)`
  - `Node.DisplayTitle()`
- Produces, for Task 3:
  - `var _ app.ToolProvider = (*App)(nil)` and `func (a *App) Tools(deps app.Deps) []app.Tool`. Task 3 appends to this list.
  - `func toolErr(err error) error`, mapping errors as in Global Constraints.
  - `func toolPath(crumbs []Node) string`, the ancestors' `DisplayTitle`s joined with `" › "`, or `""` at top level.

Today is `a.store.now().Local()`, as handlers.go uses it.

| Name | Title | Args | Result |
|---|---|---|---|
| `notes_search` | Search notes | `query` (required), `limit` (optional, default 20, at most 50) | JSON `{"results":[{"id","title","note"?,"done"?,"due"?,"path"?}]}` |
| `notes_get` | Read part of the outline | `id` (optional; 0 or missing = the whole outline from the top), `depth` (optional, default 3, from 1 to 10) | Indented plain text (format below), passed through `CapToolText` |
| `notes_due` | Notes with due dates | none | JSON `{"overdue":[…],"today":[…],"this_week":[…],"later":[…]}`. Each entry is `{"id","title","due","path"?}`. Empty groups are `[]`. |

The search result's `note` field is the first 200 runes of the bullet's note, followed by `…` when it was longer. Search passes `showCompleted=true`, so done bullets match too and come back with `"done":true`.

**`notes_get` text format.** This is the algorithm that the signature and tests don't fully settle:
- With an id, start with `Path: <toolPath>` when the bullet has ancestors. Then the bullet itself at indent 0. Then `Outline(ctx, userID, id, true, true)` filtered to `n.Depth < depth`, each line at indent `n.Depth+1`.
- Without an id, there is no path and no root line. Show `Outline(ctx, userID, RootID, true, true)` filtered to `n.Depth < depth`, each line at indent `n.Depth`.
- Each bullet is one line: `<2 spaces × indent>- <DisplayTitle> [id <ID>]`. Then append ` [done]` if done, ` (due <DueOn>)` if it has a due date, and ` (+<ChildCount> more)` if `ChildCount > 0` and its children fall past the depth limit.
  - For the root line, use `ChildCount` from `ByID`'s node when depth is 0. Otherwise its children are listed.
- A bullet's note, when not empty, follows on its own lines. Each line is indented two spaces deeper than the bullet and prefixed with `| `.
- An empty outline gives `Your outline is empty.`
- An id whose node is `Archived` gives the not-found `ToolError`.

The descriptions must tell the model when to use each tool:
- **search:** to find a bullet by words, and the ids to pass to `notes_get`.
- **get:** to read a list or project. Use the ids it shows for `notes_add` and `notes_set_done`.
- **due:** for "what do I need to do?".

## Task 3: Notes write tools — add, set done

**Files:**
- Create: `internal/apps/notes/tools_write.go`
- Modify: `internal/apps/notes/tools.go` (`Tools` list)
- Test: `internal/apps/notes/tools_write_test.go`, `internal/apps/notes/tools_test.go` (`TestNotesToolsDeclared` → 5)

**Interfaces:**
- Consumes: `toolErr`, `toolPath` (Task 2); `Store.ByID`, `Store.Create(ctx, userID, parentID, afterPos, title, note)`, `Store.SetDone(ctx, userID, id, done)`, `RootID`.

| Name | Title | Args | Idempotent | Result |
|---|---|---|---|---|
| `notes_add` | Add a note | `text` (required), `parent_id` (optional; missing or 0 = top level) | false | `{"id","title","parent_id"?,"path"?}` |
| `notes_set_done` | Tick a note done | `id` (required), `done` (required bool) | true | `{"id","title","done"}` |

`notes_add`:
1. Normalise `\r\n` to `\n`.
2. Split at the first `\n`. The title is the first line, trimmed. The note is the rest, trimmed.
3. If the title is empty after trimming, refuse with `Give the note some text.`
4. If `parent_id` is set, `ByID` it first. An archived parent gives the not-found `ToolError`. Without this check `Create` would accept it, but the new bullet would vanish under an archived parent.
5. `Create(ctx, userID, parentID, math.MaxInt32, title, note)` appends as the last child (`Create` clamps the position).
6. `path` is the parent's path plus the parent's title.

`notes_set_done`: `ByID` first, so an archived bullet gives not-found. Then `SetDone`. The result is the bullet's title and the new state.

Descriptions:
- **add:** adds a bullet at the end of the parent's children, or at the top level. Get a parent's id from `notes_search` or `notes_get`. Text after the first line becomes the bullet's note.
- **set_done:** ticks a bullet done, or un-ticks it with `done=false`. Ticking a parent doesn't tick its children.
