# AI access P2 — ON Books write tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A connected assistant with the `books:write` scope can start a book, record progress, finish it (with an optional rating), mark it DNF, and add notes and quotes.

**Architecture:** Six new `app.Tool`s in `internal/apps/books/tools.go` (and a new `tools_write.go`), each a thin wrapper over an existing `Store` method. Store `Refusal`s become `app.ToolError`s so the model hears the same sentence a person sees in the UI. The platform gains one field, `app.Tool.Idempotent`, which becomes the MCP `idempotentHint`. No migrations, no new routes, no new dependencies.

**Tech Stack:** Go 1.27, `modelcontextprotocol/go-sdk` v1.8.0 (already in `go.mod`), SQLite store as today.

**Spec:** `docs/superpowers/specs/2026-11-24-ai-access-mcp-design.md` ("Tool rules", "Tool list" → Books, "Phases" → P2). P1 plan for reference: `docs/superpowers/plans/2026-11-24-ai-access-p1.md`.

## Global Constraints

- Tool set is exactly the spec's six write tools (Ilia, 2026-11-25: "spec only" — no `books_rate`, no `books_add`): `books_start_reading`, `books_update_progress`, `books_finish`, `books_mark_dnf`, `books_add_note`, `books_add_quote`.
- Every write tool: `Scope: "books:write"`, `ReadOnly: false`. `Registry.Tools` already refuses a `:write` tool marked read-only.
- `Call` uses only the `userID` it is given; the book ID comes from the arguments and every store method already scopes it to that user.
- A missing book and another user's book give the same message, verbatim: `No book with that ID on your shelves` (as `books_get` does today).
- Store refusals reach the model as their own text (`Refusal.Msg`) via `app.ToolError`; any other error stays a plain error, so the platform logs it and the model sees "Something went wrong."
- Annotations (spec, "Tool rules"): writes keep `destructiveHint=false` (P1 already sets it); `idempotentHint=true` only where a repeat call changes nothing: start, finish, DNF. Progress, note and quote each add a row, so `false`.
- Malformed arguments: the model sees the fixed message `The arguments are not valid.` and never Go's `json` error text (closes the "Books tools argument errors" item of #629, which applies to all Books tools).
- Results are compact JSON, empty fields left out (existing `toolBook` projection).
- Dates the model passes are `YYYY-MM-DD`, validated by the store (`checkDay`); empty means today.
- No deletes (spec, "Decisions at a glance").

## Review Focus

1. **Progress in the "wrong" unit.** "I'm 40% through" on a paper book counted in pages, or "page 120" on an audiobook. The tool converts when the book has a page count, and refuses with a clear sentence when it can't.
2. **A write on a book not being read** (progress, finish or DNF on a Want or Read book). The store's `This book isn't being read right now.` must reach the model, not "Something went wrong."
3. **Both or neither of `page` and `percent`.** A clear refusal, not a silent zero recorded as progress.
4. **A read-only connection.** A grant with only `books:read` must not list or call any write tool. The scope filter is P1's, but P2 is the first time real write tools exist, so prove it end to end.
5. **Rating out of range or a future finish date.** A readable sentence reaches the model, not "Something went wrong." (the store's `checkRating` returns a bare `ErrInvalid`, so the tool checks the rating itself), and nothing is written.

  - `func (a *App) bookResult(ctx context.Context, userID, id int64) (string, error)`: re-reads the book with `Store.Get` and returns `marshalTool` of the same `toolBook` projection `books_get` builds (factor the projection out of `getTool` into `func bookToolView(b Book) toolBook` rather than copying it). Tool definitions (names, scopes and idempotency are fixed; tune the description wording, keep the content):

| Name | Title | Args struct | Idempotent | Description must say |
|---|---|---|---|---|
| `books_start_reading` | Start reading | `idToolArgs{ID int64 \`json:"id"\`}` | true | Starts a new reading today: the first, or a re-read of a finished book. Refused if the book is already being read. |
| `books_update_progress` | Update progress | `progressToolArgs{ID int64; Page int \`json:"page,omitempty"\`; Percent int \`json:"percent,omitempty"\`}` | false | Records where the user is in a book they're reading. Give exactly one of page or percent. Reaching the end doesn't finish the book; use books_finish. |
| `books_finish` | Finish a book | `finishToolArgs{ID int64; Rating int \`json:"rating,omitempty"\`; Day string \`json:"day,omitempty"\`}` | true | Marks the book being read as finished, today unless day (YYYY-MM-DD) is given. rating 1–5 rates it; leave it out to keep the current rating. |
| `books_mark_dnf` | Stop reading (DNF) | `dnfToolArgs{ID int64; Day string \`json:"day,omitempty"\`}` | true | Marks the book being read as did-not-finish, today unless day is given. |

`jsonschema` tags describe each argument, as the read tools' args do. Only `id` is required (no `omitempty`).

- [ ] **Step 3: Implement**

- `parseToolArgs`: return `app.ToolError{Msg: "The arguments are not valid."}`. Drop `err.Error()`.
- `toolErr`, `bookToolView` and `bookResult` as in Interfaces. Switch `getTool` to `toolErr`.
- `progressTool` conversion. This is the one piece of logic the tests don't fully determine:
  1. Exactly one of `Page` and `Percent` must be non-zero. Otherwise refuse with `Give either page or percent.` (0 can't be recorded through the tool. A voice user never says "page 0", and this keeps the both/neither check simple.)
  2. `Store.Get` the book (`toolErr` on error). The unit is `UnitFor(b.Latest.Format, b.Pages)`.
  3. Value in the book's unit: pass it through. Percent on a page-unit book: `value = round(percent * pages / 100)`. Page on a percent-unit book: if `b.Pages > 0`, `value = round(page * 100 / pages)`; else refuse `This book has no page count, so give a percentage.`
  4. `Store.RecordProgress(ctx, userID, id, value)` → `toolErr`. The store's range check gives the out-of-range messages.

  Use integer rounding (`(a*b + c/2) / c`). Don't range-check before the store: its messages are the ones the tests pin.
- Finish: the tool checks `0 <= Rating <= 5` itself and refuses with `rating must be a whole number from 1 to 5.`, because the store's `checkRating` returns a bare `ErrInvalid` (not a `Refusal`), which would reach the model as "Something went wrong." Then `FinishReading(ctx, userID, in.ID, strings.TrimSpace(in.Day), in.Rating)`. DNF: `MarkDNF(..., day, 0)`. Start: `StartReading`.
